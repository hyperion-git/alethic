## 1. Conceptual Framework

### 1.1 The Unifying Principle: Adaptive Evidence Accumulation (AEA)

Every mechanism in Alethic — stall detection, error taxonomy, physics checks, dynamic N,
adversarial verifier — is an instance of the same operation:

> Given the current evidence state, allocate the next compute unit to the action most
> likely to resolve the remaining uncertainty.

Formally: `evidence_state → (oracle_type, oracle_params, resource_budget)`

Currently this logic is fragmented across `agent.py` in separate `if/elif` branches.
v3.4 begins the consolidation: an `EvidenceState` dataclass becomes the shared
representation, and oracle selection becomes an explicit routing step in the orchestrator
loop. Full unification into an `OracleRouter` class is v4.0 infrastructure; v3.4
introduces the necessary primitives.

### 1.2 The Verification Ladder

Verification is not monolithic. It is a hierarchy of oracles with different cost and
reliability profiles. The correct policy is: only ascend to a higher layer if lower
layers pass. A dimensional failure at Layer 0 terminates the verification pass without
consuming a Layer 3 LLM call.

```
Layer 0: Structural   — type-level constraints, near-zero cost, hard filters
Layer 1: Behavioral   — known-instance checks, low cost, regression tests
Layer 2: Consistency  — cross-representation agreement, medium cost
Layer 3: Semantic     — LLM verifier, high cost; adversarial variant for thorough/extreme
Layer 4: Post-hoc     — K-consensus, highest cost; post-loop only, borderline accepts
```

Layers 0–2 are **programmatic oracles**: deterministic, cheap, domain-specific.
Layer 3 is the **LLM oracle**: flexible, expensive, adversarially self-correcting.
Layer 4 is **consensus**: multiple independent LLM oracles, reserved for near-threshold
final verdicts (implemented via the existing `/alethic-verify` pipeline).

The ladder applies to **both math and physics** with domain-specific instantiations:

| Layer | Physics | Math |
|-------|---------|------|
| 0: Structural | `verify_dimensions()` — unit balance via sympy.physics.units | `verify_structure()` — degree homogeneity, scalar/vector type consistency |
| 1: Behavioral | `verify_limit_NAME()` — known limits (c→∞, ℏ→0, T→0, weak coupling) | `verify_base_case(n=0,1,2,3)` — small instances, boundary/degenerate cases |
| 2: Consistency | `verify_symbolic_numeric()` — symbolic + numeric agreement | `verify_dual()` — closed form vs. recursive, generating function vs. direct; also `verify_step_N()` (existing) |
| 3: Semantic | Physics LLM verifier (existing) | Math LLM verifier (existing) |
| 4: Post-hoc | K-consensus via /alethic-verify (existing) | K-consensus via /alethic-verify (existing) |

**Key insight for math:** Layer 1 behavioral checks (`verify_base_case`) are the
mechanically executed form of the balanced approach addendum's counterexample
exploration. The generator is already asked to try n=0,1,2,3; making those explicit
verify functions turns that exploration into a checkable oracle that leaves behind
verifiable evidence. If n=2 falsifies the claim, the function proves it.

### 1.3 Oracle-Routed Verification

Error taxonomy (1.2, already implemented) classifies verifier critique into:
`algebra`, `logic`, `citation`, `interpretation`, `units`, `missing_case`, `general`.

v3.4 extends the taxonomy output from a revision string to a **routing decision**:

| Error category | Revision strategy | Next oracle |
|---------------|-------------------|-------------|
| `units` | Re-derive with explicit unit tracking | Layer 0: `verify_dimensions()` |
| `algebra` | Recompute all steps from scratch | Layer 2: `verify_step_N()` sandbox replay |
| `logic` | Examine each inference independently | Layer 3: adversarial verifier (force-enable) |
| `citation` | Cite or prove every invoked theorem | Layer 3: LLM verifier + (future) web search |
| `interpretation` | Re-read problem, state it in own words | Layer 3: backward verification + problem restatement |
| `missing_case` | Enumerate all cases exhaustively | Layer 1: `verify_base_case()` + escalate N |
| `general` | General revision | Layer 3: LLM verifier |

The routing table is the key addition. Implementation: `error_taxonomy.py` returns
`(revision_addendum: str, next_oracle: OracleType, force_adversarial: bool)` instead
of just a string. The orchestrator reads `next_oracle` to decide what Layer 3 parameters
to apply.

## 2. Feature 2.4 — Adaptive Compute (Dynamic N)

### 2.1 Architecture

**Principle:** Generation (wrong approach, wrong ansatz) is the primary failure mode in
math/physics. More candidates = more diverse approaches = higher probability one is
correct. Verification quality is adequate with the existing adversarial verifier; adding
K verifiers inside the GVR loop compounds errors via same-model sycophancy.

**Decision rule:**

```
Iteration 1: always N=1 (probe)
After iteration 1:
  classify_difficulty(confidence, error_category) → difficulty
  if difficulty == EASY:    keep N=preset_n  (no change needed)
  if difficulty == MEDIUM:  N = preset_n     (activate if N was 1)
  if difficulty == HARD:    N = preset_max_n (escalate fully)

difficulty = EASY   if confidence >= threshold * 0.95
difficulty = MEDIUM if confidence >= threshold * 0.75 AND
                       error_category in {algebra, citation}     # revise-first
difficulty = HARD   if confidence < threshold * 0.75 OR
                       error_category in {logic, missing_case,
                                          interpretation, units}  # need new approach
```

**Rationale for error-category split (Codex gpt-5.4):**
- `algebra`, `citation`: fixable in place — a correct approach with a sign flip or missing
  citation does not need diverse alternative candidates, it needs repair
- `logic`, `missing_case`, `interpretation`, `units`: require categorically different
  approach — more candidates from the same starting point would all share the error

**Integration with stall_reset:**
- `stall_reset` fires on confidence plateau regardless of dynamic N state
- When both fire simultaneously: stall_reset boost is additive on top of dynamic N level
- Dynamic N sets the floor; stall_reset is a temporary boost above that floor

**Budget cap:**
- `adaptive_budget_cap: int | None` — max total oracle calls (N generates + verifies + revises)
  across the full session
- Expressed as a shared resource pool (not per-iteration) for future tree-search composability
- When cap is reached: return best solution seen with a budget-exhausted note in session metadata
- Default: `None` (no cap); recommended for extreme preset: `total_calls = 3 * preset_estimate`

### 2.2 New AgentConfig Fields

```python
adaptive_compute: bool = True     # enable difficulty-based N escalation
                                   # default True in default/thorough/extreme; False in quick
adaptive_budget_cap: int | None = None  # max total oracle calls; None = unlimited
```

`quick` preset: `adaptive_compute=False` (too few iterations for probe to be useful)
`default` preset: `adaptive_compute=True` (probe at N=1, escalate to N=2 on hard problems)
`thorough` preset: `adaptive_compute=True` (probe at N=1, escalate to N=3)
`extreme` preset: `adaptive_compute=True` (probe at N=1, escalate to N=5)

### 2.3 EvidenceState Dataclass (new, partial — full OracleRouter is v4.0)

```python
@dataclass
class EvidenceState:
    iteration: int
    best_confidence: float
    error_category: str           # from classify_errors()
    confidence_history: list[float]
    iteration_shape: str          # oscillation/stall/regression/improving
    dynamic_n: int                # current N level (may differ from config.best_of_n)
    oracle_calls_used: int        # for budget cap tracking
    domain_check_results: dict    # Layer 0-2 results keyed by function name
```

`EvidenceState` is updated after each iteration and passed to:
- `_check_stall()` (reads `confidence_history`, `iteration_shape`)
- `_compute_dynamic_n()` (reads `best_confidence`, `error_category`)
- `_select_next_oracle()` (reads `error_category`, `domain_check_results`)

### 2.4 Tree-Search Composability (architectural prep)

To avoid a dead end when v4.0 adds verifier-guided tree search:

1. **`generate()` gains `partial_solution: str | None = None` parameter** — unused in v3.4,
   but establishes the interface for extending a partial solution prefix in tree search
2. **`rank_candidates()` extracted as a pluggable function** — currently an inline
   `max(candidates, key=lambda c: c.confidence)` call; extracted to
   `agent.py::rank_candidates(candidates, verifications, evidence_state) -> int`
   so PUCT scoring can replace max-confidence selection in v4.0 without changing callers
3. **Budget cap as shared resource pool** — implemented as a session-level counter
   decrement, not per-iteration, so the same pool can be allocated across tree nodes

### 2.5 Skill Parity

Orchestrator changes (`skills/alethic-common/orchestrator.md`):
- After Step 2b (initial verification): read confidence from verification file
- Compute `dynamic_n` using the same decision rule as the Python library
- On iterations 2+: use `dynamic_n` as `candidates_this_iter` (overrides preset default
  if difficulty is HARD)
- Track `oracle_calls_used` in session.json for budget cap enforcement

No new reference files needed — this is orchestrator logic only.

## 3. Feature 2.1 — Programmatic Verifier Stack

### 3.1 Architecture

The generator (physics or math) is prompted to emit verification functions alongside
the solution text, building on the existing `verify_step_N()` infrastructure from 1.6.
The sandbox evaluates all functions immediately. Results are embedded in the solution
text as ground truth for the LLM verifier.

The LLM verifier receives enhanced instructions: embedded check results are externally
observed facts (like published experimental data). If `verify_dimensions()` reports
a dimensional mismatch, treat this as `[MAJOR]` evidence regardless of how plausible
the algebra looks. Only reach Layer 3 (LLM semantic check) if Layers 0–2 pass.

### 3.2 Physics: New Generator Function Types

```python
# Layer 0: Structural — dimensional balance
def verify_dimensions():
    """Check that key equations are dimensionally consistent."""
    import sympy.physics.units as u
    # Example: verify E = mc^2 is dimensionally correct
    E = u.energy; m = u.mass; c = u.speed_of_light
    lhs_dim = u.Dimension(E)
    rhs_dim = u.Dimension(m * c**2)
    assert lhs_dim == rhs_dim, f"Dimensional mismatch: {lhs_dim} != {rhs_dim}"
    print("DIMENSIONS OK")

# Layer 1: Behavioral — known limits
def verify_limit_nonrelativistic():
    """Test that the result recovers classical mechanics in the c→∞ limit."""
    import sympy as sp
    c, m, v = sp.symbols('c m v', positive=True)
    relativistic_energy = m * c**2 / sp.sqrt(1 - v**2/c**2)
    classical_approx = sp.series(relativistic_energy, v/c, 0, 3)
    # Should recover m*c^2 + m*v^2/2 to leading order
    kinetic_term = sp.Rational(1, 2) * m * v**2
    residual = sp.simplify(classical_approx.removeO() - m*c**2 - kinetic_term)
    assert residual == 0, f"Non-relativistic limit failed: residual = {residual}"
    print("LIMIT OK: recovers classical KE in c→∞")

# Layer 2: Consistency — symbolic + numeric agreement
def verify_symbolic_numeric(params=(1.0, 2.0, 3.0)):
    """Check symbolic expression agrees with numeric evaluation."""
    import sympy as sp; import numpy as np
    m_val, v_val, c_val = params
    # Symbolic result
    m, v, c = sp.symbols('m v c')
    symbolic_result = sp.sqrt(m**2 * c**4 + m**2 * v**2 * c**2)
    sym_val = float(symbolic_result.subs({m: m_val, v: v_val, c: c_val}))
    # Direct numeric computation
    num_val = np.sqrt(m_val**2 * c_val**4 + m_val**2 * v_val**2 * c_val**2)
    assert abs(sym_val - num_val) < 1e-10, f"Symbolic/numeric mismatch: {sym_val} vs {num_val}"
    print(f"CONSISTENCY OK: {sym_val:.6f} == {num_val:.6f}")
```

**Sentinel prefix:** All programmatic check functions print a machine-readable sentinel
`ALETHIC_L{N}_CHECK:` at the start of output, where N is the layer number. This allows
the verifier to distinguish authentic sandbox outputs from generator-written text.

### 3.3 Math: New Generator Function Types

```python
# Layer 0: Structural — degree/type consistency
def verify_structure():
    """Check that the result is structurally well-typed."""
    import sympy as sp
    n = sp.Symbol('n', positive=True, integer=True)
    # Example: verify sum formula is a polynomial of correct degree
    result = n * (n + 1) * (2*n + 1) / 6  # claimed sum of squares formula
    assert sp.Poly(result, n).degree() == 3, "Expected degree-3 polynomial in n"
    # Check it's actually a polynomial (no negative powers)
    assert result.is_polynomial(n), "Formula contains non-polynomial terms"
    print("ALETHIC_L0_CHECK: STRUCTURE OK")

# Layer 1: Behavioral — base/boundary cases
def verify_base_cases():
    """Verify the formula gives correct results for small instances."""
    import sympy as sp
    n = sp.Symbol('n')
    formula = lambda k: k * (k + 1) * (2*k + 1) / 6
    expected = {0: 0, 1: 1, 2: 5, 3: 14, 4: 30}
    for k, exp in expected.items():
        got = int(formula(k))
        assert got == exp, f"n={k}: expected {exp}, got {got}"
    print("ALETHIC_L1_CHECK: BASE CASES OK (n=0,1,2,3,4)")

# Layer 2: Consistency — dual representation
def verify_dual_representation(n_test=10):
    """Verify closed form matches direct summation for a concrete n."""
    formula = lambda k: k * (k + 1) * (2*k + 1) // 6
    direct = sum(i**2 for i in range(n_test + 1))
    closed = formula(n_test)
    assert direct == closed, f"Dual check failed: direct={direct}, closed={closed}"
    print(f"ALETHIC_L2_CHECK: CONSISTENCY OK at n={n_test} ({direct}=={closed})")
```

## 5. Verification Ladder: Failure Mode Analysis

### The Decoupling Tension (Q5 from brainstorm)

The decoupling principle (verifier never sees generator reasoning) is preserved because:
- The verifier sees **outputs** of sandbox execution (externally observable facts),
  not the generator's reasoning traces (internally constructed arguments)
- This is analogous to a reviewer accepting that an author's simulation produced the
  stated output while still independently checking whether the simulation code is correct

**Primary risk:** Generator fabricates `ALETHIC_L1_CHECK: BASE CASES OK` as literal text
rather than actual sandbox output. **Mitigation:** The sentinel `ALETHIC_L{N}_CHECK:` is
produced by the sandbox tool result, not the LLM — the tool-use round returns actual
execution output. Verifier can treat absence of sentinel as suspicious.

**Secondary risk:** Generator writes a `verify_base_case()` function that tests a proxy
condition (easier to satisfy than the actual intermediate goal). **Mitigation:** Adversarial
verifier scrutinizes function definitions, not just outputs. This is an existing
responsibility of the adversarial self-critique protocol.

## 7. Design Decisions (resolved by council: Gemini 3.1 Pro + Codex gpt-5.4 + Opus ultrathink, 3/3 unanimous)

### Q1: `adaptive_compute` (N-probe) in `default` preset?

**Decision: NO. Enable in `thorough`/`extreme` only. Add adaptive revision budget for `default`.**

All three agents against enabling N-probe in `default`:
- The first iteration matters most; best-of-2 selection materially helps medium-difficulty
  problems (the dominant default use case); probing at N=1 first loses precisely there
- "Easy" threshold (0.855) < acceptance threshold (0.90) — a plausible first attempt gets
  locked at N=1 revise-first when N=2 would still buy diversity (Codex)
- `default` already has an adaptive escape hatch via `stall_reset`
- Ship as opt-in/experimental first; benchmark before promoting (Codex)

**New sub-feature for `default`: Adaptive revision budget.**
Keep N=2 always. After iteration 1, adapt `max_revisions_this_iter`:
- `error_category in {algebra, citation}` AND confidence >= 0.80 → reduce to 1 revision
  (quick patch is likely sufficient; saves revision compute on easy fixable errors)
- confidence < 0.70 → increase to min(max_revisions+1, 5)
  (hard problem needs more repair effort)
This adapts compute within the revision cycle without changing generation strategy or
surprising users with unpredictable first-iteration quality.

**Preset table update:**
- `quick`: `adaptive_compute=False`
- `default`: `adaptive_compute=False`, `adaptive_revision_budget=True` (new)
- `thorough`: `adaptive_compute=True`
- `extreme`: `adaptive_compute=True`

### Q2: Layer 0–2 checks in `/alethic-verify` + `/alethic-check`?

**Decision: Tiered hybrid by solution provenance.**

All three agents against reconstructing L0–2 functions from arbitrary external text.
Opus proposed the hybrid (require verifiers to write+run checks); Codex added the
provenance key insight.

**Tier 1 — Alethic-generated solutions** (contain `ALETHIC_L{N}_CHECK:` or
`verify_step_N()` sentinels): parse and consume embedded check outputs as ground truth.
Zero extra cost; the generator already did the work.

**Tier 2 — External solutions** (arbitrary text, no sentinels): inject a
`verification-ladder.md` reference that directs each K LLM verifier to write and
execute their own structured check functions using the existing sandbox (SymPy, NumPy,
SciPy via `PYTHON_TOOL`). Verifiers embed outputs as `[Layer N check]: {result}`.
Layer 0 failure = immediately `[MAJOR]` regardless of analytic quality of the derivation.

This is strictly better than either pure option:
- Better than "no checks" (Gemini's fallback): provides programmatic grounding and audit trail
- Better than "reconstruct from text": no generator co-operation required; each verifier
  independently derives and runs its own check (which also serves as verification diversity)

**New files:**
- `skills/alethic-verify/references/verification-ladder.md`
- `skills/alethic-check/references/verification-ladder.md`

**New `VerifierConfig` field:** `verification_ladder: bool` (default True); injected via
`extra_system` in `_run_single_verify()`. Sentinel parsing added to `verify-orchestrator.md`.
