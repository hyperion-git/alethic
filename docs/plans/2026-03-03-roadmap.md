## Forward Plan: v3.6.5 → v4.0

### v3.6.5 — Housekeeping

- Commit untracked documentation (design specs, evaluation plans)
- Refresh this roadmap (done)
- Simplification pass on codebase
- No behavioral changes

### v3.7 — OracleRouter + Search Primitives

**Theme:** Refactor internals, build measurement infrastructure. Zero behavioral change.

- **OracleRouter class**: centralize fragmented `if/elif` oracle dispatch (deferred from v3.4)
- **TreeNode / SearchPath primitives**: data structures for nodes, visit counts, PUCT scores
- **`rank_candidates()` generalization**: accept pluggable scoring strategy (max-confidence vs PUCT)
- **Expanded benchmark suite**: physics benchmark, harder problems — establish v3.6 baseline
- **Atom annotation frequency measurement**: determines Option E vs F for v3.8

**Benchmark gate at v3.7 exit:**
- `(delta_solve_rate / baseline_solve_rate) > (delta_cost / baseline_cost)`
- ≥10% atom-driven solve-rate improvement → v3.8 leans Option E (atom graph traversal)
- Marginal → v3.8 leans Option F (PUCT over flat solutions)

### v3.8 — Shallow Tree Search

**Theme:** Replace flat loop with structured search, depth-limited.

- **`partial_solution` wiring**: generator continues from prefix (parameter exists, unused)
- **Shallow tree search**: depth-limited (3–5 levels), expand → evaluate → prune → select
- **PUCT scoring**: plug into generalized `rank_candidates()` from v3.7
- **Breaker + stall composition**: wire into new loop at manageable depth
- **Cost controls**: budget cap across tree nodes

### v3.9 — Deep Search + Process Supervision

**Theme:** Remove depth limits, add step-level scoring.

- **Unbounded tree depth** + context window management
- **Intra-generation pruning**: backtrack during generation (deferred from v3.4)
- **Process supervision (3.3)**: step-level scoring, score propagation through tree
- **Fabrication mitigation**: hash provenance for sandbox outputs (deferred from v3.4)

### v4.0 — Release Milestone

**Theme:** Benchmark-gated release, documentation, skill parity decision.

- Benchmark regression gate (must beat v3.6 on expanded suite)
- Cost analysis (tree search API call overhead)
- Failure mode / autopsy comparison vs v3.6
- Skill parity decision: rewrite orchestrator.md or declare Python-library-only
- Roadmap refresh for v5.0+
