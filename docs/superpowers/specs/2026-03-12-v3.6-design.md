## Section 1: Architecture Overview

v3.6 adds two capabilities on top of the v3.5 atom infrastructure:

1. **Atom-guided verification** (verifier side): the verifier receives a focus directive indicating which atoms to scrutinize with full LLM attention (HIGH priority) vs reduced attention (REDUCED priority), based on their stability history and oracle-level evidence.

2. **Confidence calibration** (calibration module): raw model confidence scores are temperature-scaled before being compared against the acceptance threshold, correcting for systematic overconfidence or underconfidence. Calibration data is accumulated across sessions in a user-local JSONL store.

## Section 2: Atom-Guided Verification

### 2.1 `_build_atom_focus_directive(atoms: list[AtomAnnotation]) -> str | None`

Produces a two-tier focus directive for the verifier. Lives in `agent.py` as a module-level function.

**Input**: the most recent iteration's atom list (`state.atom_history[-1]` at the call site — guarded against empty history with `if state.atom_history` before indexing).

**Tier assignment** for non-synthetic atoms:

| Condition | Tier |
|-----------|------|
| `oracle` in {LAYER3_LLM, LAYER3_LLM_ADVERSARIAL, LAYER4_CONSENSUS} | **HIGH** |
| `oracle` in {L0, L1, L2} AND sentinel results non-empty at that oracle's layer | **REDUCED** |
| `oracle` in {L0, L1, L2} AND sentinel results empty/absent at that oracle's layer | **HIGH** |
| `AtomStability.STABLE` | Omitted from directive |
| `atom.synthetic == True` | Excluded entirely |

**D1 proxy**: `parse_layer_results()` returns `dict[int, list[str]]` — raw strings, not pass/fail booleans. The proxy for "passing" is: non-empty list at the atom's oracle layer → presume passed (REDUCED). Empty/absent → HIGH.

**Known limitation**: Non-empty sentinel text that is actually a failure report (e.g., `"ALETHIC_L1_CHECK: FAILED — mismatch"`) is non-empty, so the proxy classifies it as REDUCED. The implementation must inspect sentinel text for failure markers (e.g., `"FAILED"`, `"ERROR"`) and route to HIGH in that case — not treat all non-empty content as passing.

**Returns**: `None` if atoms is empty, all atoms are STABLE, or all atoms are synthetic.

**D8 RESOLVED (Option C)**: `_build_atom_focus_directive` returns `None` for all-synthetic atom lists. This is intentional — the feature is annotation-dependent by design. Options that inject a directive referencing a non-existent "ATOM[0]" structural label (Options A and D) were rejected because they either cause spurious verifier behavior (A: verifier may flag the absent atom-0 label as a defect) or fail in partial-annotation transitions (D: ATOM[0] reference conflicts with real atom maps). The generator prompt's "monolithic" escape hatch is tightened (see generator prompt update below) to increase annotation coverage from ~40-50% to ~65-75% of iterations.

**Generator prompt update (D8 Option C)**: In `GENERATOR_SYSTEM` and `PHYSICS_GENERATOR_SYSTEM`, replace the existing escape-hatch line:

> "If your solution is monolithic (not naturally decomposable), omit the atom headers — the verifier will treat the whole solution as a single atom."

With the tightened version:

> "Omit atom headers ONLY for single-step computations or arguments with no separable sub-claims (e.g., a one-line algebraic check). For all other proofs and derivations — including case splits, inductions, multi-step algebraic derivations, and anything requiring more than two logical inferences — atom annotations are required."

Apply the same tightening to the corresponding skill reference files `skills/alethic-solve/references/generator.md` and `skills/alethic-derive/references/generator.md`.

### 2.2 `_build_atom_context(atom_history, confidence_history) -> str | None`

Produces a stability advisory for the reviser. Lives in `agent.py` as a method on `MathAgent`, parallel to `_build_reset_context()` (lines 340–366).

**Guards**:
- `len(atom_history) < 2` → `None` (insufficient history)
- All-synthetic atom history → `None` (no real atoms to track); this guard must be explicit — verified by spying that `classify_atom_stability` is NOT called (not just that the return is `None` by accident)
- `config.variant_b is not None` → `None` (variant-B diversity strategy supersedes atom stability strategy; same guard as `_build_reset_context`)
- Empty stability dict → `None`

**Advisory text** (mutual exclusivity enforced):
- STABLE atoms: "do not discard these atoms — they represent verified correct steps"
- OSCILLATING atoms: warn against repeating previous approaches (must NOT contain "do not discard")
- FAILING atoms: acknowledge declining confidence and advise categorical change

**Injection point**: appended to `revise()` user message **after** the low-confidence sections block (if any), as `atom_context: str | None = None` kwarg on `revise()` in `subagents.py`.

**Spy target for tests**: `@patch("alethic.agent.classify_atom_stability")` — not `alethic.atoms.classify_atom_stability` — because `classify_atom_stability` is imported into `agent.py` scope.

### 2.3 `_combine(a: str | None, b: str | None) -> str | None`

```python
def _combine(a: str | None, b: str | None) -> str | None:
    parts = [x.strip("\n") for x in (a, b) if x]
    return "\n\n".join(parts) or None
```

Strips leading/trailing newlines from each non-falsy part before joining, so that any combination of trailing/leading newlines normalizes to exactly `"\n\n"` as separator. Empty string collapses like `None`.

Contract:
- `_combine(None, None)` → `None`
- `_combine("a", None)` → `"a"`
- `_combine(None, "b")` → `"b"`
- `_combine("", "b")` → `"b"`
- `_combine("a", "b")` → `"a\n\nb"`
- `_combine("text\n\n", "more")` → `"text\n\nmore"` (trailing newlines stripped)
- `_combine("text", "\n\nmore")` → `"text\n\nmore"` (leading newlines stripped)
- `_combine("text\n", "more")` → `"text\n\nmore"` (single trailing newline also normalized)

**Usage** for verifier `extra_system`:
```python
extra_system = _combine(self._adversarial_addendum(), directive)
```
Adversarial addendum always comes first; atom focus directive appended after.

**D4 RESOLVED (Option 3)**: Call sites A and B receive the atom focus directive; call site C does not.

- **Call site A** (`_verify_candidates()`, line ~521): `extra_system = _combine(self._adversarial_addendum(), directive)` where `directive = _build_atom_focus_directive(state.atom_history[-1]) if state.atom_history else None`. Prior-iteration atom stability is the primary intended signal — the feature's core use case.
- **Call site B** (`_run_revision_loop()`, line ~607): same `_combine` pattern. `state.atom_history[-1]` at this point contains the current iteration's winning candidate's atoms (appended at line 930, before `_run_revision_loop` is called at line 1136). The pre-revision atom stability profile correctly identifies which atoms need heightened scrutiny in the revised version.
- **Call site C** (FIXABLE shortcut, line ~1073): unchanged — `extra_system=self._adversarial_addendum()` only. Rationale: the corrected solution is unannotated (the verifier does not produce `ATOM[N]` markers), so the directive's HIGH/REDUCED tier assignments are structurally inapplicable. Minority concern noted (D4-Scientist-2): REDUCED labels at call site B may suppress scrutiny of revision-introduced errors in previously-stable atoms. Mitigation: the adversarial verifier protocol (5-round self-critique) provides baseline full-scrutiny coverage regardless of tier assignments.

## Section 3: Confidence Calibration

### 3.1 Temperature scaling

```python
def calibrate(raw: float, T: float) -> float:
    """Apply temperature T to raw confidence. T=1 is identity."""
    if T == 1.0:
        return raw
    raw_clipped = max(1e-7, min(1 - 1e-7, raw))
    return float(sigmoid(logit(raw_clipped) / T))
```

- T > 1: compresses probabilities toward 0.5 (corrects overconfidence)
- T < 1: pushes toward extremes (corrects underconfidence)
- `calibrate(0.0, T) == 0.0`, `calibrate(1.0, T) == 1.0` (boundary fixpoints via clip)
- Identity short-circuit at T=1.0 for exact floating-point equality

### 3.2 Threshold calibration

```python
calibrated_threshold = calibrate(raw_threshold, T)
```

This preserves the acceptance-rate invariant: a raw confidence passes the raw threshold iff the calibrated confidence passes the calibrated threshold.

**FIXABLE threshold split**: The FIXABLE re-verify shortcut uses `raw_threshold` (not `calibrated_threshold`), because the corrected solution is re-verified before calibration is applied to the main loop. All other accept-gate checks use `calibrated_threshold`.

### 3.3 `fit_temperature(pairs, *, grid_points=50) -> float`

Finds T that minimizes NLL on historical (raw_conf, solved) pairs.

- Grid: 50 log-space points in `[0.05, 20.0]`; argmin via grid scan + Brent's refinement
- Returns T=1.0 (identity) when `len(pairs) < 20`
- Version filter: include only pairs with same `major.minor` version as current `alethic.__version__`
- NOTE: Version filter semantics (`major.minor` equality) must be confirmed during evaluation (see D8 note — the exact filter policy is an open design detail)

### 3.4 `calibration.py` module structure

```python
# New module: src/alethic/calibration.py

JSONL_SCHEMA = {
    "model": str,           # model name from AgentConfig
    "preset": str,          # preset name
    "best_of_n": int,       # N used
    "raw_conf": float,      # raw verifier confidence from winning candidate
    "solved": bool,         # True if agent returned CORRECT verdict
    "ts": str,              # ISO timestamp
    "alethic_version": str  # alethic.__version__ at time of recording
}

def _default_store() -> Path:
    """Lazy path — evaluated at call time, never at module import."""
    p = Path.home() / ".alethic" / "calibration.jsonl"
    p.parent.mkdir(parents=True, exist_ok=True)
    return p

def append_pair(raw_conf, solved, *, model, preset, best_of_n, store_path=None): ...
def load_pairs(*, store_path=None) -> list[dict]: ...
def fit_temperature(pairs, *, grid_points=50) -> float: ...
def calibrate(raw: float, T: float) -> float: ...
def load_calibrated_threshold(raw_threshold, *, store_path=None) -> float: ...
```

**Path convention**: `~/.alethic/calibration.jsonl` (user-home, persistent across projects). This is a new path convention not established by `session.py` (which uses project-local `.alethic/` or `/tmp/`). The rationale: calibration data is model-level, not project-level — sharing across projects is beneficial.

### 3.5 Integration with `solve()`

- `calibration.py` imported lazily (to avoid breaking installs that don't use calibration)
- `AgentConfig` gains `apply_calibration: bool = True` and `calibration_store: str | None = None`
- At `solve()` start: load T via `load_calibrated_threshold(config.confidence_threshold)`; compute `calibrated_threshold = calibrate(config.confidence_threshold, T)`
- At `solve()` end: `append_pair(raw_conf=winning_confidence, solved=result.verdict == Verdict.CORRECT, ...)`
- Stall detection still uses raw confidence (calibration applied only at the accept gate)

## Section 4: Data Flow and Error Handling

### 4.1 Verifier output format

New output section between ISSUES and SECTION CONFIDENCES:

```
VERDICT: CORRECT
CONFIDENCE: 0.94
CRITIQUE: ...
REASON: ...
ISSUES:
- [MINOR] ...
ATOM CONFIDENCES:
ATOM[1]: 0.97
ATOM[2]: 0.88 step 3 algebra may have a sign error
ATOM[3]: 0.95
SECTION CONFIDENCES:
Setup: 0.96
Computation: 0.89
Conclusion: 0.94
CORRECTED SOLUTION:
...
END CORRECTED SOLUTION
```

### 4.2 `AtomConfidence` dataclass

```python
@dataclass
class AtomConfidence:
    id: int
    confidence: float
    note: str | None = None
```

Parse format: `ATOM[N]: 0.NN optional note text`

The bracket syntax (`ATOM[N]:`) was chosen specifically because `\n[A-Z]+:` (the `_parse_section_confidences` outer boundary regex) does NOT match it — the `[N]` breaks the `[A-Z]+` pattern. This prevents ATOM CONFIDENCES lines from being captured as the start of a SECTION CONFIDENCES block.

However: this also means the `_parse_section_confidences` outer boundary cannot stop at `ATOM CONFIDENCES:` (which contains a space — also breaks `[A-Z]+`). This is handled by placing `ATOM CONFIDENCES:` strictly BEFORE `SECTION CONFIDENCES:` in the output, so the section-confidences parser starts AFTER the atom block.

### 4.3 `VerificationResult` changes

```python
@dataclass
class VerificationResult:
    # ... existing fields unchanged ...
    atom_confidences: list[AtomConfidence] = field(default_factory=list)  # new
```

Both existing construction sites use keyword args → no changes needed. Default empty list ensures backward compatibility.

### 4.4 Parser fixes

**`_parse_issues()` stop-word addition** (live v3.5 bug — fix immediately):

Current:
```python
r"ISSUES:\s*\n(.*?)(?=\nREASON:|\nSECTION CONFIDENCES:|\Z)"
```

Fixed:
```python
r"ISSUES:\s*\n(.*?)(?=\nREASON:|\nATOM CONFIDENCES:|\nSECTION CONFIDENCES:|\Z)"
```

**`_parse_section_confidences()` atom guard**:

Inside the per-line parser loop, add guard before processing each line:
```python
if re.match(r"ATOM\[\d+\]", line.strip()):
    continue  # skip atom confidence lines that bled past ATOM CONFIDENCES block
```

Note: The regex `ATOM\[\d+\]` only catches single-integer IDs. If the LLM produces `ATOM[1,2]:` or similar multi-ID format, the guard does not trigger and the line is ingested as a spurious SectionConfidence. This is a known limitation; the format spec (`ATOM[N]:`) is enforced in prompts.

### 4.5 FIXABLE threshold split

When the FIXABLE shortcut re-verifies the corrected solution, use `raw_threshold` (not `calibrated_threshold`), because:
1. The shortcut fires within an iteration before the calibration bookkeeping runs
2. The corrected solution hasn't been through the full accept pipeline
3. Using raw threshold for the shortcut is conservative (harder to accept)

```python
# In FIXABLE shortcut path:
if re_verification.is_acceptable(raw_threshold):  # raw, not calibrated
    return self._make_result(corrected, ...)

# In main accept gate:
if verification.is_acceptable(calibrated_threshold):  # calibrated
    break
```

4. `ATOM[1]: 0.88` → `AtomConfidence(id=1, confidence=0.88, note=None)` — assert `note is None` (not `note == ""`)
5. `ATOM[2]: 0.91 minor algebra error` → `note == "minor algebra error"` (full note text, not truncated)
6. Full round-trip through `_parse_verification()`: input text with ATOM CONFIDENCES block → `result.atom_confidences` populated

**`_parse_section_confidences()` guard:**
7. Baseline (document pre-fix): SECTION CONFIDENCES block containing `ATOM[3]: 0.77` → `ATOM[3]` ingested as spurious `SectionConfidence` (because `\n[A-Z]+:` terminator does NOT match `ATOM[1]:` — the `[N]` breaks the pattern)

**`_parse_verification()` CRITIQUE boundary:**
10. CRITIQUE: correctly stops at `\nREASON:|\nISSUES:|\nSECTION CONFIDENCES:|\Z` — safe with ISSUES→ATOM CONFIDENCES ordering (CRITIQUE never spans ATOM CONFIDENCES)

**`REASON:` parser note**: The `REASON:` block currently stops at `\nISSUES:`. Since `ATOM CONFIDENCES:` appears after `ISSUES:` in the output format, the REASON parser is not affected. Confirm with a regression test: REASON block is not extended by presence of ATOM CONFIDENCES block.

## Resolved Design Decisions

### D4: Which `verify()` call sites receive the atom focus directive?

**Decision: Option 3** (call sites A and B, not C). Resolved 2026-03-12 via 3-agent evaluation swarm (2/3 majority; 1 dissent for Option 2).

- **Call site A** (`_verify_candidates`, line ~521): receives directive. Prior-iteration atom stability is the primary intended signal for the feature.
- **Call site B** (`_run_revision_loop`, line ~607): receives directive. `state.atom_history[-1]` at this call site contains the current iteration's winning candidate's atoms (appended at line 930, before `_run_revision_loop` is invoked at line 1136). The pre-revision stability profile correctly identifies which atoms need heightened scrutiny in the revised version.
- **Call site C** (FIXABLE shortcut, line ~1073): does NOT receive directive. The corrected solution is produced by the verifier as unannotated prose — directive HIGH/REDUCED assignments reference atom IDs that do not exist as structural markers in the corrected solution text. Including the directive would either confuse the verifier (it searches for non-existent ATOM[0] markers) or cause misdirection on a fast-lane exit path with no recovery round.

**Minority concern** (1/3 agents, D4-Scientist-2): REDUCED labels at call site B may suppress scrutiny of revision-introduced errors in previously-stable atoms. For example: ATOM[1] is STABLE → REDUCED in directive; reviser rewrites ATOM[1]'s content and introduces a new sign error; call site B under-scrutinizes the rewritten section. **Mitigation**: the adversarial verifier protocol's 5-round self-critique (`ADVERSARIAL_VERIFIER_ADDENDUM`) mandates that the verifier independently verify every accepted step regardless of tier assignments. The REDUCED tier reduces re-derivation effort, not skepticism about logical correctness.

### D8: How should the atom-focus directive handle the monolithic fallback?

**Decision: Option C** (annotation-dependent, strengthen generator prompt). Resolved 2026-03-12 via unanimous 3-agent evaluation swarm.

- `_build_atom_focus_directive` behavior is unchanged — returns `None` for all-synthetic atom lists. This is correct behavior: no annotation information means no targeting is possible.
- Options A and D were rejected because they reference a non-existent "ATOM[0]" structural label in the solution text. Option A risks spurious defect flags (verifier may penalize the absent label as a missing structural element). Option D fails in partial-annotation transitions where real atom maps exist alongside the synthetic ATOM[0] reference.
- Option B was rejected as redundant noise: the generic "full scrutiny" message duplicates what the adversarial self-correction protocol and stall reset addendum already provide; its confidence-based trigger threshold (< 0.80) is arbitrary and does not compose cleanly with presets that use different thresholds.
- The generator prompt's monolithic escape hatch (existing line 93–94) is the dominant cause of non-engagement (~50-60% of iterations). Tightening the escape hatch to require explicit justification increases estimated engagement from ~40-50% to ~65-75% of iterations at zero implementation cost.
- **Implementation**: prompt-only change (see Section 2.1 for exact text). No code change to `_build_atom_focus_directive`, `classify_atom_stability`, or any data models.
