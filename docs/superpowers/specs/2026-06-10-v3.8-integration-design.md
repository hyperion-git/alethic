# v3.8 Integration — Wiring Tree Search into AgentConfig, Agents, CLI, and Eval

## Overview

PR #10's four commits landed the v3.8 hierarchical proof search as standalone modules
(`proof_graph.py`, `microkernel.py`, `explorer.py`, `search.py`) with `search.solve()`
as a self-contained entry point. This spec covers the deferred integration
(`search.py` module docstring, lines 16–20): exposing tree search through the standard
`MathAgent`/`PhysicsAgent` API, the CLI, and the eval harness, plus checkpoint/resume
and consumption of the v3.8 oracle-routing scaffolding.

Parent spec: `docs/superpowers/specs/2026-04-11-v3.8-tree-search-design.md`.

## Decisions (user-approved 2026-06-10)

1. **Rollout: opt-in first.** `search_mode` defaults to `"flat"` for ALL presets.
   The parent spec's preset table (default/thorough/extreme → tree) is applied only
   after the benchmark gate passes, as part of the v4.0 release — at that point the
   flip is a preset-table edit, nothing more.
2. **Scope:** core wiring + oracle-routing scaffolding consumption + eval-harness
   pass-through + tree-mode checkpoint/resume.
3. **Out of scope:** variant-B bridge diversity (parent spec open question 4 — needs
   calibration data first), router-driven flat→tree escalation (v3.9+ candidate),
   preset flip, any skill counterpart (tree search is library-only per
   `docs/skill-parity.md`).
4. **Architecture: dispatch inside `MathAgent.solve()`** (approach A). A separate
   subcommand (B) would fork the user API and force a retrofit at preset-flip time;
   router-driven escalation (C) needs flat-vs-tree data that doesn't exist yet.

## 1. Config surface (`models.py`)

**`SearchConfig` moves from `search.py` to `models.py`.**

- Rationale: `AgentConfig` gains a `SearchConfig`-typed field; `models.py` importing
  from `search.py` would be circular (`search.py` already imports `AgentConfig`,
  `AgentResult`, etc. from `models.py`). `models.py` is also the established home of
  every config dataclass.
- The class moves verbatim (fields, `__post_init__` validation, `PRESETS`,
  `from_preset()`). `search.py` keeps `from alethic.models import SearchConfig` and
  re-exports it so existing imports (`from alethic.search import SearchConfig`) and
  all 49 `test_search.py` tests keep working unchanged.
- Export `SearchConfig` from `alethic/__init__.py`.

**`AgentConfig` gains exactly two fields:**

```python
search_mode: str = "flat"            # "flat" (current GVR loop) | "tree" (v3.8 search)
search: SearchConfig | None = None   # tree-search knobs; None → SearchConfig() at dispatch
```

- `__post_init__` validates `search_mode in {"flat", "tree"}` (ValueError otherwise).
- No preset rows change. `from_preset()` accepts the new fields as overrides like any
  other field.
- `build_variant_b_config()` is unaffected (variant B applies to flat-path candidate
  generation only).

## 2. Agent dispatch (`agent.py`)

Early branch at the top of `MathAgent.solve()`, before flat-path state setup:

```python
if self.config.search_mode == "tree":
    return self._solve_tree(
        problem, balanced=balanced,
        resume_from=resume_from, create_session=create_session,
    )
```

`_solve_tree()` (~40 lines):

1. Create the session directory via the existing `create_session_dir()` when
   `create_session=True` (same `.alethic/` / `/tmp/alethic-*/` logic as flat;
   skipped when resuming — the resume dir is reused).
2. Call `search.solve(problem, config=self.config,
   search_config=self.config.search or SearchConfig(), domain=self._domain(),
   client=self._client, ledger=<agent ledger>, balanced=balanced,
   session_dir=session_dir, resume_from=resume_from)`.
3. On completion: write `output.md` and `worklog/events.jsonl` into the session dir
   (final write only — no per-iteration incremental worklog in tree mode), attach
   `session_dir` to the returned `AgentResult`.

`PhysicsAgent` requires **zero changes**: `_domain()` already returns `"physics"`,
which routes the microkernel and explorer to the physics prompt sets.

The flat path is byte-for-byte untouched.

## 3. Tree-mode checkpoint/resume (`proof_graph.py`, `session.py`, `search.py`)

**Serialization.** `AtomNode.to_dict()/from_dict()` and
`ProofGraph.to_dict()/from_dict()` — plain-JSON round-trip covering all fields
including PUCT state (`visit_count`, `total_value`, `techniques_tried`), `status`,
`level`, `parent_id`, `child_ids`. `AtomStatus` serializes as its string value.

**Checkpoint write.** New `session.write_tree_checkpoint(session_dir, *, graph,
bridge_attempts, failed_bridges, gap_states, best_solution_text, best_confidence,
token_ledger)` writes:

- `tree_state.json`:
  ```json
  {
    "mode": "tree",
    "version": "<alethic __version__>",
    "bridge_attempts": 1,
    "failed_bridges": ["..."],
    "graph": { "atoms": {...}, "next_id": 12 },
    "gap_states": { "<atom_id>": { "technique_attempts": 2, "last_error_category": "logic", ... } },
    "best_confidence": 0.74,
    "token_usage": { "input": ..., "output": ... }
  }
  ```
- `worklog/best_solution.md` (same convention as flat checkpoints).
- Updates `session.json` with `"status": "checkpoint", "mode": "tree"`.

**Checkpoint trigger.** `search.solve()` gains `session_dir: str | None = None` and
`resume_from: str | None = None`. On `ContextExhaustedError` /
`TruncatedResponseError` it checkpoints **itself** (the live graph/gap state is in
its locals — threading it out to the agent would be strictly worse) and returns a
partial UNSOLVED `AgentResult` with `checkpoint_path` set. With `session_dir=None`
(library callers that opted out of sessions) the exception propagates unchanged —
current behavior preserved.

**Resume.** `resume_from` loads `tree_state.json`, reconstructs `ProofGraph` and the
per-gap `_GapState` map, and re-enters Phase 3 (gap-filling) of the checkpointed
bridge; if that bridge's gaps were already exhausted, it proceeds to Phase 4
(re-bridge) under the restored `bridge_attempts` counter.

**Mode mismatch.** Resuming a directory whose checkpoint lacks `tree_state.json`
while `search_mode == "tree"`, or one that has it while `search_mode == "flat"`,
raises `CheckpointError` naming both the found and expected modes.

## 4. Oracle-routing scaffolding consumption (`microkernel.py`, `search.py`)

`MicrokernelTask` gains two fields with frozen-safe defaults (all existing
construction sites and tests remain valid):

```python
oracle: OracleType | None = None     # advisory routing target, logged for analysis
force_adversarial: bool = False      # inject adversarial verifier addendum
```

- **Search layer:** on a *retry* attempt at a gap (i.e. `_GapState.last_error_category`
  is set from a prior `MicrokernelResult`), look up
  `_ORACLE_ROUTING[last_error_category]` → `(oracle, force_adversarial)` and set both
  fields on the next `MicrokernelTask`. First attempts keep the defaults.
- **Microkernel:** when `force_adversarial` is true, pass the domain's adversarial
  addendum (`ADVERSARIAL_VERIFIER_ADDENDUM` / `PHYSICS_ADVERSARIAL_VERIFIER_ADDENDUM`)
  as `extra_system` to its `verify()` calls. `oracle` is recorded in the result/event
  data only — the verification-ladder layers (L0–L2) are embedded checks the
  microkernel cannot toggle per-call, so pretending to "route" to them would be
  dishonest. This closes the parent spec's "`_ORACLE_ROUTING` → wire into microkernel"
  row with the actionable subset.
- The `RoutingDecision.next_oracle` / `force_adversarial` fields stay flat-path
  scaffolding (the flat loop's adversarial behavior is already governed by
  `AgentConfig.adversarial_self_correction`); their docstring comments are updated to
  point at the tree-path consumption.

## 5. CLI (`cli.py`) and eval harness (`eval/harness.py`)

- New global flag for solve/derive: `--search {flat,tree}` (default `flat`). When
  `tree`: `search_mode="tree"` and `search=SearchConfig.from_preset(<preset>)` for
  presets in `SearchConfig.PRESETS`; `quick` (absent there) falls back to
  `SearchConfig()` defaults.
- `alethic eval run` gains the same flag → `run_benchmark(..., search_mode="flat")`
  pass-through. The report dict gains `"search_mode"`; per-problem results gain
  `"bridges_used"` and `"gaps_filled"` extracted from the result's event log when in
  tree mode (null in flat mode).
- `--json` output: no schema change beyond the fields above (events already carry the
  tree-search detail).

## 6. Error handling

| Condition | Behavior |
|-----------|----------|
| `search_mode` not in {flat, tree} | `ValueError` from `AgentConfig.__post_init__` |
| `search` set while `search_mode == "flat"` | Allowed, ignored (harmless; documented) |
| Tree resume on flat checkpoint (or vice versa) | `CheckpointError` naming found vs expected mode |
| `tree_state.json` unreadable/corrupt | `CheckpointError` (mirrors flat `load_checkpoint`) |
| Context exhaustion mid-search, session dir present | Self-checkpoint + partial result (§3) |
| Context exhaustion, no session dir | Exception propagates (current behavior) |

   with restored visit counts (mock subagents); mode-mismatch raises.
5. **Microkernel routing:** `force_adversarial=True` → adversarial protocol text in
   `verify()`'s `extra_system`; defaults produce today's exact call shape.
6. **CLI/eval:** `--search tree` parses into config correctly for both subcommands;
   `run_benchmark` pass-through; report fields present.
